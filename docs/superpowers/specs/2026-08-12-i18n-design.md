# WireGuard GUI 多语言（i18n）设计说明

- 日期：2026-08-12
- 分支：`feature/i18n`
- 状态：已确认，待编写实现计划

## 1. 目标

为 WireGuard GUI 增加多语言支持，覆盖前端全部可见文案与 Linux 桌面元数据。

支持语言（5 种）：

| locale | 原生名 | 角色 |
| --- | --- | --- |
| `en` | English | fallback 兜底语言 |
| `zh-CN` | 简体中文 | |
| `zh-TW` | 繁體中文 | 独立词条，非简繁机械转换 |
| `ja` | 日本語 | |
| `ru` | Русский | 复数四档 |

## 2. 现状与约束

- **技术栈**：Tauri v2 + Next.js 16（`output: 'export'` 静态导出）+ React 19 + shadcn/ui + Tailwind 4。
- **窗口**：400 × 642，`resizable: false`。
- **后端错误已编码化**：Rust 侧统一返回 `AppError::coded("<code>", "<英文消息>")`，前端已有两处 `byCode` 映射表把 code 转成英文文案。**本次不修改任何 Rust 代码。**
- **e2e 无文本断言**：`e2e/specs/security-flow.spec.ts` 全部使用 `data-testid` 选择器，改文案不会破坏测试。
- **App Router 无内置 i18n**：静态导出下路由式多语言（`/zh/`、`/en/`）不可用，且 Tauri 只加载 `index.html`，路由方案本身也不适用。

## 3. 技术选型

采用 **react-i18next + i18next**，纯客户端实例，5 份词条静态 import 全量打包（合计约 20KB，无懒加载）。

不选 `next-intl`：其核心价值在基于路由的多语言，静态导出的桌面应用用不上，需退化到 no-routing 模式，反而绕。

不选自研 Context：单复数（尤其俄语四档）与插值需自行实现，收益不抵成本。

不引入 `@tauri-apps/plugin-os`：系统语言用 `navigator.languages` 即可获得（WebKitGTK 中反映系统 locale），可省下一个 Rust 依赖、一个 JS 依赖和一条 capability 权限。

不引入 `i18next-browser-languagedetector`：需要自定义 `zh-HK → zh-TW` 等降级规则，自写 `detect.ts` 更直接。

新增依赖仅两个：`i18next`、`react-i18next`。

## 5. 语言解析与持久化

优先级：`localStorage['wg-gui-locale']` → 系统语言 → `en`。

匹配规则（遍历 `navigator.languages`，取第一个能匹配上的）：

1. 精确命中 `SUPPORTED_LOCALES` → 直接采用。
2. `zh-HK`、`zh-MO`、`zh-Hant*` → `zh-TW`。
3. `zh`、`zh-Hans*`、其他 `zh-*` → `zh-CN`。
4. 主语言标签命中（如 `ja-JP` → `ja`、`ru-RU` → `ru`、`en-GB` → `en`）→ 采用。
5. 均不匹配 → `en`。

用户在切换器中手动选择后写入 `localStorage`，此后以手动选择为准，不再跟随系统。

### 水合（hydration）处理

静态导出会在构建期把界面预渲染成 HTML。因此：

- i18next 初始化 **必须** 使用固定的 `lng: DEFAULT_LOCALE`（`en`），保证客户端首次渲染与预渲染 HTML 一致。
- 在 `I18nProvider` 的 `useEffect` 中再调用 `i18n.changeLanguage(resolveLocale())`。
- 同一个 effect 中设置 `document.documentElement.lang = locale`（`app/layout.tsx` 的 `<html lang="en">` 是服务端渲染的静态值，无法直接动态化）。

若在首次渲染就使用解析后的语言，中文用户会触发 React 水合不匹配报错。切换发生在挂载后的同一帧，且被现有的 1 秒启动闪屏（`AppSplashScreen`）覆盖，用户不可见。

## 6. 词条组织

单命名空间（默认 `translation`），按功能分组：

```
common.*    通用：cancel、continue、save、loading、noResults
app.*       主界面：windowTitle、notConnected、ipUndetected、connecting、disconnecting、
            disconnect、logoTitle、resetSuccess、resetFailed、lockedByInactivity、connectionError
profile.*   配置管理：列表表头、增删改查按钮 title、表单标签与校验、导入导出 toast、搜索框
security.*  安全面板：加密开关、PIN 提示、解锁面板、重置确认
errors.*    以后端错误码为 key
language.*  语言切换器：触发按钮 title
```

约 75 条词条。

### 错误码即 key

删除 `app/page.tsx` 与 `components/security-controls.tsx` 中两处硬编码的 `byCode: Record<string, string>` 映射表，替换为共用 helper：

```ts
// lib/i18n/error.ts
export function useErrorMessage() {
  const { t } = useTranslation();
  return (e: CommandError) =>
    t(`errors.${e.code}`, { defaultValue: e.message || t('errors.unknown') });
}
```

后端新增错误码时，前端无需改代码即可兜底显示后端英文消息，补词条即完成本地化。

需要覆盖的错误码（合并两处映射表）：`activation_failed`、`import_failed`、`invalid_profile_name`、`nmcli_missing`、`permission_denied`、`profile_exists`、`profile_not_found`、`pin_incorrect`、`profiles_locked`、`script_failed`、`timeout`、`encryption_already_enabled`、`encryption_not_enabled`、`invalid_pin`，外加 `errors.unknown`。

### 整句化

`components/profile-dialog-form.tsx` 现有 `{editId ? 'Edit' : 'Create'} profile` 属于句子拼接，中文与日文语序不同，必须拆成两个完整词条 `profile.dialog.editTitle` / `profile.dialog.createTitle`。实现时不得保留任何以词为单位的字符串拼接。

### 不翻译的内容

- 配置内容占位符（`contentPlaceholder`，WireGuard 配置模板）
- 示例配置名占位符 `wgnet0`
- 文件选择器扩展名过滤 `.conf`
- 品牌名 `WireGuard`
- 语言切换器中的语言名（固定显示原生名，这是 i18n 惯例）

## 7. 单复数

仅 `components/profile-table.tsx` 的导入/导出结果 toast 需要复数，共 4 条：

- `profile.importSuccess`（含 `{{count}}`、`{{names}}`）
- `profile.importPartial`（含 `{{count}}`、`{{failed}}`）
- `profile.exportSuccess`
- `profile.exportPartial`

使用 i18next 的复数后缀，底层走 `Intl.PluralRules`：

| locale | 需要的后缀 |
| --- | --- |
| `en` | `_one`、`_other` |
| `zh-CN` / `zh-TW` / `ja` | `_other` |
| `ru` | `_one`、`_few`、`_many`、`_other` |

俄语四档（1 / 2–4 / 5+ / 小数）是本次选择俄语带来的额外维护成本，校验脚本需按语言规则分别校验，不能一刀切要求所有语言 key 集合完全相同。

## 8. 语言切换器

位置：`app/page.tsx` header 行，现有盾牌（安全设置）按钮**左侧**，作为第三个图标按钮。

- 图标：lucide `Languages`
- 交互：`DropdownMenu`（`components/ui/dropdown-menu.tsx` 已存在）
- 菜单项：5 个原生名，当前语言带勾选标记
- `data-testid="language-switcher"`，菜单项 `data-testid="language-option-<locale>"`
- 切换即时生效，无需重启

宽度核算：3 个图标按钮约 120px，400px 窗口容纳无压力。

## 9. 窗口标题与桌面元数据

### 窗口标题

运行时通过 `getCurrentWindow().setTitle(t('app.windowTitle'))` 跟随语言变化。

`core:window:allow-set-title` 权限**已存在**于 `src-tauri/capabilities/migrated.json`，无需修改 capability。

品牌名 `WireGuard` 保留，仅本地化其后的描述性部分：

| locale | `app.windowTitle` |
| --- | --- |
| `en` | WireGuard GUI |
| `zh-CN` | WireGuard 图形客户端 |
| `zh-TW` | WireGuard 圖形用戶端 |
| `ja` | WireGuard クライアント |
| `ru` | Клиент WireGuard |

### 桌面文件

已核实 Tauri v2 的 `bundle.linux.deb.desktopTemplate` 与 `bundle.linux.rpm.desktopTemplate` 支持自定义 Handlebars 模板，可用变量：`name`、`comment`（可选）、`exec`、`icon`、`categories`。

新增 `src-tauri/templates/main.desktop`，在标准字段基础上补充本地化条目：

```
[Desktop Entry]
Categories={{categories}}
Exec={{exec}}
Icon={{icon}}
Name={{name}}
Terminal=false
Type=Application
StartupNotify=true

GenericName=VPN Client
GenericName[zh_CN]=VPN 客户端
GenericName[zh_TW]=VPN 用戶端
GenericName[ja]=VPN クライアント
GenericName[ru]=VPN-клиент

Comment=A WireGuard client GUI
Comment[zh_CN]=WireGuard 客户端图形界面
Comment[zh_TW]=WireGuard 用戶端圖形介面
Comment[ja]=WireGuard クライアントの GUI
Comment[ru]=Графический клиент WireGuard
```

`Name` 为产品名，不本地化。`.desktop` 使用 POSIX 风格 locale 后缀（`zh_CN`，下划线），与 BCP 47 的 `zh-CN` 不同，注意不要混用。

`tauri.conf.json` 中在 `bundle.linux.deb` 与 `bundle.linux.rpm` 下分别指向该模板。

### 已知限制（不在本次范围）

- **AppImage** 没有独立的 `desktopTemplate` 配置项。按 Tauri 打包流程它复用 deb 产物中的桌面文件，预期可继承本地化条目，但**需真机打包验证**，本设计不对此作出保证。
- **Snap Store 元数据**（`snap/snapcraft.yaml` 的 `summary` / `description` / `title`）属于商店侧多语言，需通过 Snap Store 的翻译机制处理，不在本次范围。Snap 内的 `.desktop` 文件来自打包产物，可继承本地化条目。

## 10. 类型安全与词条校验

5 份词条手工维护极易漏 key，设两道防线：

1. **编译期**：`types/i18next.d.ts` 通过 `CustomTypeOptions` 以 `en.json` 为准推导 key 联合类型，`t('errors.typo')` 直接触发 TS 报错。
2. **校验脚本**：`scripts/check-i18n.mjs` 以 `en.json` 为基准，逐语言比对 key 集合，按各语言的 `Intl.PluralRules` 规则展开复数后缀后校验，发现缺失或多余即非零退出。

`package.json` 中新增 `"check-i18n": "node scripts/check-i18n.mjs"`，并将 `lint` 改为 `"eslint . && npm run check-i18n"`，使校验进入既有的 lint 流程。

## 12. 明确不做（YAGNI）

- 不修改 `components/ui/` 下未被应用实际渲染的上游 shadcn 文件：`dialog.tsx` 的 `Close` 按钮（应用未使用 `DialogFooter`）、`pagination.tsx` 与 `spinner.tsx` 的 aria-label、`breadcrumb.tsx` 的 aria-label。仅修改两个可达文件：项目自写的 `alert-confirm.tsx`（`Cancel` / `Continue`）与已被定制过的 `data-table.tsx`（`No results.`）。
- 不做词条懒加载、不做 RTL 支持、不做日期与数字本地化（应用中无日期展示）。
- 不修改任何 Rust 代码。
- 不修改窗口的 `resizable` 设置。

## 13. 风险

窗口固定 `400 × 642` 且不可缩放。俄语与日语文案显著长于英文，以下位置有撑破或截断风险：

- `security-controls.tsx` 的整宽按钮：`Enable encryption` → `Включить шифрование`
- `security-controls.tsx` 的说明段落与 `UnlockPanel` 的提示文字
- `AlertConfirm` 的重置确认描述（较长）
- header 增加第三个图标按钮后的横向空间

处理方式：允许换行，不使用 `whitespace-nowrap`，实现时逐语言核对。不通过修改窗口尺寸或 `resizable` 来规避。

## 14. 验收标准

必须全部通过：

1. `npm run lint` 通过（含新增的 `check-i18n`）。
2. `npm run next-build` 通过（静态导出成功）。
3. `node scripts/check-i18n.mjs` 通过，5 份词条 key 集合按各自复数规则完整。
4. `app/` 与 `components/`（不含第 12 节声明豁免的 `ui/` 文件）中不残留面向用户的硬编码英文字面量。
5. 无 React 水合不匹配警告。
6. 现有 e2e spec 未作修改仍应可用（本地无法运行，见下）。

### 本环境的验证边界

当前环境**没有 Rust 工具链，也没有 webkit2gtk 开发库**，`tauri dev`、`tauri build`、`npm run e2e` 均无法运行。

因此以下项**无法在本环境验证**，需在具备 Rust 工具链的机器上确认：

- `.desktop` 模板的实际打包产物（deb / rpm / AppImage）
- 运行时窗口标题切换效果
- 五种语言在 400px 窗口中的真实排版

实现完成后将明确列出哪些验收项已实测通过、哪些待你在打包环境确认，不会含糊带过。
